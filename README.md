# Twenty One Landing

Build a responsive marketing website for a mobile app called Twenty One.

Product

Twenty One is a calm, reflective habit-change app.

The app helps people step away from a habit for 21 days and understand what happens along the way. It is not a productivity tracker, streak counter, or gamified habit app.

The core idea is:

21 days. One conscious choice at a time.


The product focuses on:
awareness instead of perfection
reflection instead of pressure
understanding personal patterns
noticing changes in wellbeing
seeing the journey as a whole
building confidence through experience

The app has a feature called Mirror of Truth, which appears after completing the 21-day challenge. It turns the user's own data, reflections and patterns into a personal summary of the journey.

Website Goal

Create a polished landing page that introduces Twenty One and makes visitors want to try the app.

The website should feel like an extension of the app itself — calm, thoughtful, personal and slightly editorial.

The website is primarily a product/marketing website, not a dashboard.

Do not build a generic SaaS landing page.

Do not use:

excessive gradients

neon colors

gamification

badges

fake statistics

generic startup illustrations

stock-photo-heavy sections

overly rounded "AI SaaS" cards

aggressive CTA language

Visual Direction

The visual language should feel:

calm

warm

minimal

human

reflective

modern

editorial

slightly poetic

premium but approachable

Think of a combination of:

modern editorial design

thoughtful wellness apps

minimalist Apple-like product presentation

a personal journal

quiet digital experiences

The design should have plenty of whitespace.

Avoid making everything look like a card.

Use typography and spacing as important design elements.

Color Palette

Use a warm, muted palette.

Primary background:

warm off-white / cream

Primary text:

dark charcoal

Secondary text:

muted warm gray

Accent:

muted sage / soft green

Secondary accent:

subtle warm beige

Avoid bright saturated colors.

The interface should work beautifully in both light and dark contexts, but the landing page should primarily use the light theme.

Typography

Use a sophisticated modern sans-serif for UI and body text.

For large emotional/editorial headlines, you may use a subtle serif or distinctive display font if it improves the design.

Typography should feel intentional rather than corporate.

Large headlines should have generous line-height and strong visual hierarchy.

Landing Page Structure

Create the following sections.

1. Navigation

Minimal navigation.

Left:
Twenty One

Center/right navigation:

How it works

Why 21 days

Mirror of Truth

CTA:
Start your 21 days

On mobile:

logo

hamburger menu

CTA

Keep navigation sticky but subtle.

2. Hero

The hero should immediately communicate the emotional idea of the product.

Headline:

21 days can change the way you see a habit.

Supporting text:

Twenty One helps you step away from a habit, notice what changes, and understand what the experience says about you.

Primary CTA:

Start your 21 days

Secondary CTA:

See how it works

Visually, show a beautiful representation of the mobile app.

Prefer a realistic iPhone mockup or carefully designed app interface rather than a generic illustration.

The phone should show the app's calm visual language.

3. The Concept

Introduce the philosophy.

Headline:

Not a streak. A journey.

Text:

Most habit apps ask:
"Did you do it today?"

Twenty One asks something different:

"What did you notice?"

Explain that the app does not punish missed days or turn progress into a competition.

It helps users observe their choices, wellbeing, thoughts and patterns over 21 days.

Create this section with strong typography and whitespace rather than a collection of cards.

4. How It Works

Three or four steps.

01 — Choose

Choose the habit you want to step away from.

02 — Notice

Each day, record what happened, how you felt, and whatever felt worth remembering.

03 — Continue

There is no need to be perfect. Keep going and let the pattern emerge.

04 — Look back

After 21 days, see the experience as a whole.

Use subtle visual transitions between the steps.

5. Daily Experience

Show the actual daily experience inside the app.

Headline:

A few minutes a day. A clearer picture over time.

Explain that users can record:

whether they stayed or slipped

mood

energy

sleep

short answers to prompts

reflections

photos

Show these features through actual UI mockups.

Do not create fake dashboard charts that don't resemble the real app.

Use screenshots/mockups that look like a coherent mobile product.

6. Data Without Pressure

Headline:

Your data should help you understand yourself — not judge you.

Explain that the app turns daily entries into patterns.

Mention examples such as:

wellbeing changes

consistency

moments worth remembering

words that appeared repeatedly

time and money saved

momentum throughout the challenge

Make it clear that statistics are used for reflection, not competition.

7. Momentum

Introduce the concept of momentum.

Headline:

Progress isn't always a straight line.

Explain:

A missed day does not erase everything before it.

Twenty One looks at the rhythm of the journey — the periods when the user stayed with their intention, how long those periods lasted, and how consistency changed over time.

Show the visual concept using a row of simple circles representing the 21 days.

Avoid calling this a "streak tracker".

Use the term:

Momentum

and optionally:

Longest cycle

The visual should feel reflective rather than gamified.

8. Mirror of Truth

This should be one of the most important sections of the website.

Headline:

At the end, the app gives you something back.

Subheadline:

Mirror of Truth

Explain that after 21 days, the app transforms the user's own experience into a personal reflection.

It can show:

how the beginning compares with the end

changes in wellbeing

moments and reflections

frequently used words

consistency and momentum

longest cycle

time saved

money saved

quantity avoided

The important idea:

The app doesn't tell you who you became. It helps you see what happened.

Visually, make this section more emotional and editorial.

Show a large phone mockup of the Mirror of Truth screen.

9. Before / After

Do NOT present this as a superficial transformation like a fitness app.

Instead compare:

Day 1
with
Day 21

Show examples such as:

"I don't know what to expect."

→

"I understand my pattern much better now."

Use subtle typography and app UI.

10. Why 21 Days?

Explain the concept behind the challenge.

Do not make unsupported scientific claims such as "21 days creates a habit."

Instead say that 21 days provides:

enough time to notice patterns

enough repetition to experience change

a defined beginning and end

a manageable commitment

Use careful language.

11. Privacy

Add a simple privacy section.

The user's reflections are personal.

Explain that personal journal data should be treated as personal.

Do not invent technical privacy claims.

If specific technical details are not provided, keep the wording general rather than making unsupported promises.

12. Final CTA

Large editorial section.

Headline:

Give yourself 21 days to find out what changes.

CTA:

Start your 21 days

Secondary text:

No perfection required.

Footer

Include:

Twenty One

Links:

How it works

Privacy

Terms

Contact

App Store CTA placeholder.

Do not invent App Store URLs.

Interactions

Use subtle interactions:

smooth scrolling

gentle fade/slide reveals

phone mockups with subtle parallax

hover states

understated button animations

navigation transitions

Animations should feel calm and intentional.

Do not use excessive animation.

Respect prefers-reduced-motion.

Responsive Design

The website must be fully responsive.

Design specifically for:

mobile

tablet

desktop

Do not simply shrink the desktop layout.

On mobile:

typography must remain readable

sections should have comfortable spacing

phone mockups should remain prominent

navigation should become a clean mobile menu

CTAs should remain easy to access

Technical Requirements

Build the website using modern React and TypeScript.

Use a clean component architecture.

Create reusable components for:

Navigation

Buttons

Section headers

Phone mockups

Feature sections

CTA sections

Footer

Keep the code maintainable.

Do not add unnecessary dependencies.

Do not create backend functionality unless explicitly requested.

Do not invent authentication, payments, user accounts or database functionality.

This first version is a marketing website / landing page.

Important Design Constraint

The website should feel like the same product as the existing iOS app.

The existing app uses:

warm minimal backgrounds

calm typography

subtle cards

muted green accents

rounded but not excessive UI elements

reflective language

generous spacing

simple iconography

The website should translate this visual language to the web instead of creating a completely different brand.

Copywriting Tone

The tone should be:

calm

honest

thoughtful

concise

human

slightly poetic

Avoid:

marketing clichés

"unlock your potential"

"transform your life"

"be the best version of yourself"

"crush your goals"

exaggerated promises

The product should feel like it is quietly saying:

"You don't need to become a different person. Just give yourself enough space to notice what is already there."

First Implementation

Start by building the complete landing page with realistic placeholder app mockups.

Prioritize:

visual quality

typography

spacing

responsive layout

product storytelling

consistency with the iOS app

Do not add unnecessary sections.

Make the first version feel polished enough to present as a real product.
